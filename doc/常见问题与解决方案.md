# 网页导航项目 - 常见问题与解决方案

本文档记录了在开发过程中遇到的核心问题及其解决方案，涵盖 Git 管理、打包部署、跨域访问三大类。

---

## 一、Git 管理

### 1. .gitignore 配置问题

#### 问题描述
- 前端大量文件（node_modules, dist 等）显示在提交列表中，导致 git status 混乱。
- 已提交的 gitignore 规则未生效。

#### 解决方案
- **配置正确的 .gitignore**：
  ```
  # Node.js / Frontend
  node_modules/
  dist/
  dist-ssr/
  *.local

  # IDE
  .idea/
  .vscode/

  # OS
  .DS_Store
  Thumbs.db
  ```
- **清除已被追踪的文件**：如果文件已经被提交到 git 历史，需要先从 git 缓存中移除：
  ```bash
  git rm -r --cached node_modules
  git rm -r --cached dist
  ```

### 2. Git 推送与远程仓库管理

#### 问题描述
- 本地有多个远程仓库（origin / github），容易推错。
- 分支没有设置 upstream，裸写 `git push` 报错。

#### 解决方案
- **查看远程仓库**：`git remote -v`
- **设置默认跟踪分支**：
  ```bash
  git push --set-upstream origin master
  # 之后裸写 git push 就会默认推到 origin 的 master 分支
  ```
- **添加/修改远程仓库**：
  ```bash
  git remote add origin <仓库地址>
  git remote set-url origin <新仓库地址>
  ```

## 二、打包与部署

### 1. Vite 打包后资源路径错误

#### 问题描述
- 部署到 GitHub Pages 后，页面白屏，控制台报 404 错误（资源加载失败）。
- 原因：vite.config.js 中 base 路径未配置或配置错误。

#### 解决方案
- 在 `vite.config.js` 中配置 `base`：
  ```javascript
  export default defineConfig({
    // 如果部署到 https://用户名.github.io/仓库名/
    // base 必须与仓库名一致
    base: '/你的仓库名/',
    // ...
  });
  ```
- **注意**：修改 base 后，`npm run preview` 本地预览时也要带上这个路径才能访问：
  - `http://localhost:4173/仓库名/`

### 2. GitHub Pages 部署失败

#### 问题描述
- GitHub Actions 构建失败。
- `pages build and deployment` 报错。

#### 解决方案
- **方案 A：手动推 gh-pages 分支（推荐）**
  ```bash
  # 1. 在 frontend 目录下 build
  npm run build
  
  # 2. 进入 dist 目录，初始化 git 仓
  cd dist
  git init
  git add -A
  git commit -m "deploy"
  
  # 3. 推送到远程仓库的 gh-pages 分支
  git remote add origin <仓库地址>
  git branch -M gh-pages
  git push -f origin gh-pages
  
  # 4. GitHub Pages 设置 → 来源选 "从分支部署"，分支选 "gh-pages"
  ```
- **方案 B：GitHub Actions 自动部署**
  - 创建 `.github/workflows/deploy.yml`，配置 CI/CD 流程
  - 在 GitHub Pages 设置中切换到 "GitHub Actions"

### 3. 本地 preview 端口不匹配

#### 问题描述
- 本地 `npm run preview` 启动后，访问 `http://localhost:8381` 打不开页面。

#### 解决方案
- Vite 默认 preview 端口是 4173
- 自定义端口在 `vite.config.js` 中配置 `preview.port`
- 如果配置了 base，访问地址必须带 base 路径

## 三、跨域与网络访问

### 1. Mixed Content 混合内容拦截（HTTPS 页面请求 HTTP API）

#### 问题描述
- GitHub Pages 是 HTTPS 站点，但后端 API 使用 HTTP（AlwaysData 免费版不支持 HTTPS）
- 浏览器直接拦截所有跨域请求，页面功能完全失效

#### 解决方案：Cloudflare Worker 反向代理

**核心思路**：在 GitHub Pages 和 AlwaysData 之间加一层 Cloudflare Worker 作为 HTTPS 中转站。

**步骤 1**：注册 Cloudflare
- 打开 https://dash.cloudflare.com
- 使用邮箱免费注册，无需信用卡

**步骤 2**：创建 Worker 并配置代理
- 在 Workers & Pages 里创建新 Worker
- 粘贴以下代码：

```javascript
export default {
  async fetch(request) {
    const url = new URL(request.url);
    url.hostname = '你的后端域名';  // 如 services-tanyouwei.alwaysdata.net
    url.port = '8380';
    url.protocol = 'http:';
    
    // 处理 CORS 预检请求
    if (request.method === 'OPTIONS') {
      const origin = request.headers.get('Origin') || '*';
      return new Response(null, {
        status: 204,
        headers: {
          'Access-Control-Allow-Origin': origin,
          'Access-Control-Allow-Methods': 'GET, POST, PUT, DELETE, OPTIONS',
          'Access-Control-Allow-Headers': 'Content-Type, Authorization',
          'Access-Control-Allow-Credentials': 'true'
        }
      });
    }
    
    const modifiedHeaders = new Headers(request.headers);
    // 关键：设置为后端 CORS 白名单已有的 Origin，绕过检查
    modifiedHeaders.set('Origin', 'http://localhost:8381');
    
    const modifiedRequest = new Request(url, {
      method: request.method,
      headers: modifiedHeaders,
      body: request.body,
      redirect: request.redirect
    });
    
    const response = await fetch(modifiedRequest);
    
    const requestOrigin = request.headers.get('Origin') || '*';
    const newResponse = new Response(response.body, response);
    newResponse.headers.set('Access-Control-Allow-Origin', requestOrigin);
    newResponse.headers.set('Access-Control-Allow-Credentials', 'true');
    newResponse.headers.set('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE, OPTIONS');
    
    return newResponse;
  }
}
```

**步骤 3**：修改前端配置
- `.env.production` 中的 `VITE_API_BASE_URL` 改为 Worker 地址：
  ```
  VITE_API_BASE_URL=https://你的-worker-name.workers.dev
  ```

**注意事项**：
- 不要在 Worker 代码中拼接 `/api` 路径，前端请求已经带了
- CORS 响应头必须使用动态 Origin（不能用 `*`），配合 `Credentials: true`
- Origin 头改为后端 CORS 白名单已有的值（如 `http://localhost:8381`）

### 2. AlwaysData 后端服务 502

#### 问题描述
- 访问 AlwaysData 后端 API 返回 502 Bad Gateway

#### 解决方案
- **检查端口**：AlwaysData 可能分配了不同的端口，修改 `application.yml` 的 port 为实际监听端口
- **检查进程**：AlwaysData 后台确认 Java 进程是否存活
- **检查 SSL**：免费版不支持 HTTPS，需用 Cloudflare Worker 代理

### 3. 后端 CORS 配置

#### 问题描述
- 本地开发正常，部署到 GitHub Pages 后 API 请求被 CORS 拦截

#### 解决方案
- 在后端 `application.yml` 的 CORS 白名单中加入以下域名：
  ```yaml
  app:
    cors:
      allowed-origins:
        - http://localhost:8381      # 本地开发
        - https://mryouwei.github.io  # GitHub Pages
        - https://*.workers.dev      # Cloudflare Worker
  ```

### 4. 为什么 GitHub Pages 不能直接访问 Alwaysdata 服务？

#### 问题描述
- 前端部署在 `https://mryouwei.github.io/...`，后端 API 地址是 `http://services-tanyouwei.alwaysdata.net:8380`
- 直接直连 API 时页面功能失效，请求被浏览器拦截

#### 根本原因：混合内容策略（Mixed Content Policy）

浏览器安全策略规定：**HTTPS 页面不允许发起 HTTP 请求**。

| 项目 | 协议 |
|------|------|
| GitHub Pages | `https://`（GitHub 强制 HTTPS） |
| Alwaysdata 后端（8380 端口） | `http://`（免费版不支持自定义端口 HTTPS） |

当前端页面运行在 `https://...` 域名下时，浏览器会直接阻止向 `http://...` 发起的请求，控制台会报类似错误：
```
Mixed Content: The page at 'https://...' was loaded over HTTPS,
but requested an insecure resource 'http://...'.
This request has been blocked; the content must be served over HTTPS.
```

**Alwaysdata 免费版限制**：8380 端口走的是 HTTP，免费套餐通常不支持给非标准端口绑定 SSL 证书，因此无法直接把后端改成 HTTPS。

### 5. 为什么代理中转不能在 GitHub Pages 上做，而要用 Cloudflare Worker？

#### 问题描述
- 既然 GitHub Pages 能托管前端代码，为什么不能顺便做一层代理中转？
- 为什么必须额外引入 Cloudflare Worker / Vercel Functions 这类服务？

#### 根本原因：GitHub Pages 是纯静态托管，没有服务端运行时

GitHub Pages 的能力边界：
- ✅ 托管 HTML / CSS / JS 静态文件
- ✅ 提供静态文件下载
- ✅ 通过 `_redirects` 做简单 301/302 重定向
- ❌ **不能发起服务端请求**（所有请求都必须从用户浏览器发出，无法"服务器代发"）
- ❌ **不能修改请求头/响应头**（无法注入 CORS、修改 Origin、加 Token）
- ❌ **不能做协议转换**（没有中间层来做 HTTPS → HTTP 的降级）
- ❌ **没有 Node.js / Python / Java 等运行时**（无法跑 Express、Nginx 等反向代理程序）

而 Cloudflare Worker 具备服务端 JavaScript 运行时，能解决以上所有问题：

```
用户浏览器 (HTTPS)
    └─→ Cloudflare Worker (HTTPS，有运行时)
            └─→ Worker 内部发起服务端 fetch → http://services-tanyouwei.alwaysdata.net:8380 (HTTP)
                    └─→ Worker 给响应加好 CORS 头 → 返回给浏览器
```

浏览器看到的整条链路都是 HTTPS，同时 CORS 也由 Worker 统一处理，不会触发任何拦截。

#### 替代方案参考

如果不想用 Cloudflare Worker，以下几种方案同样可行：

| 方案 | 说明 | 成本 |
|------|------|------|
| Cloudflare Workers（当前方案） | 边缘计算，免费额度 10 万请求/天 | 免费 ✓ |
| Alwaysdata 启用 HTTPS | 将后端改到 443 标准端口并配 SSL | 可能需升级付费套餐 |
| Vercel / Netlify Functions | Serverless Functions 写代理接口 | 免费额度够用 |
| Railway / Render 等 PaaS | 平台默认提供 HTTPS 域名 | 免费额度有限 |
| Nginx 反向代理 | 自己有服务器时，Nginx 做 HTTPS→HTTP 反代 | 需要服务器 |

## 九、登录状态与 Cookie 优化（Shiro Session + Remember Me）

### 1. 为什么登录后很快就失效了？

#### 问题描述
- 用户登录后，过几个小时或关闭浏览器重开，就需要重新登录
- 希望像豆包、DeepSeek 等网站一样，"感觉一直没有失效过"

#### 根本原因

原始配置只有单一的 Session 机制，存在两个短板：

| 问题 | 说明 |
|------|------|
| **过期时间太短** | `setGlobalSessionTimeout(2h)` = 2 小时没访问就过期 |
| **没有持久化 Cookie** | 关浏览器后 JSESSIONID 会被浏览器清除，重开即失效 |

#### 解决方案：双 Cookie 机制（主力 + 备份）

在浏览器中同时存两个独立的 Cookie，分工配合：

```
┌─ 浏览器 Cookie ─────────────────────────────────────────┐
│                                                          │
│  ① JSESSIONID   ← Session（主力）   ② rememberMe ← 记住我（备份）
│     有效期：7 天 滑动                  有效期：30 天 固定
│     存的是：登录状态                    存的是：加密后的用户名
│                                                          │
└──────────────────────────────────────────────────────────┘
```

| Cookie | 类型 | 过期方式 | 作用 |
|--------|------|----------|------|
| `JSESSIONID` | Session（主力） | **7 天滑动过期** | 每次访问后端时，自动续期回 7 天 |
| `rememberMe` | Remember Me（备份） | **30 天固定过期**（登录那天开始算） | JSESSIONID 丢失/过期时，自动帮你重建登录 |

---

### 2. 核心概念：滑动过期 vs 固定过期

| 概念 | 说明 | 例子 |
|------|------|------|
| **滑动过期（Sliding Expiration）** | 每次访问都会刷新过期时间 | JSESSIONID：只要你偶尔访问，就永不过期 |
| **固定过期（Fixed Expiration）** | 从创建那天开始倒计时，到点必失效 | rememberMe：30 天后一定会过期，需重新登录 |

> **类比**：
> - 滑动过期 ≈ 健身房年卡：只要你每月来一次，一直给你续期
> - 固定过期 ≈ 电影院团购票：购买日起 3 个月有效，过期作废

---

### 3. 常见场景分析

#### 场景 A：每天都使用网站，持续 31 天
```
Day 0  登录 → JSESSIONID(剩7天) + rememberMe(剩30天)
Day 1  访问 → JSESSIONID 续期回 7 天（滑动生效）
Day 2  访问 → JSESSIONID 续期回 7 天
...
Day 29 访问 → JSESSIONID 续期回 7 天（rememberMe 还剩 1 天）
Day 30 访问 → rememberMe 过期，但 JSESSIONID 还剩 6 天 ✅ 正常用
Day 31 访问 → JSESSIONID 还剩 5 天 ✅ 正常用
Day 38 访问 → JSESSIONID 第31天访问后 +7天 = Day38 过期 ❌
              → 此时 rememberMe 也过期（Day30 就没了）
              → 需要重新登录 🔒
```
**结论**：每天使用 = 至少能撑到「最后一次访问 + 7 天」

#### 场景 B：7 天没访问网站
```
Day 0  登录 → JSESSIONID(剩7天) + rememberMe(剩30天)
... 中间 7 天完全没访问 ...
Day 8  访问 → JSESSIONID 已过期 ❌
              → 后端检查 rememberMe：还剩 22 天 ✅
              → 自动帮你重建新的 JSESSIONID
              → 你感觉："咦？我没登录怎么进来了" 🎩
```
**结论**：rememberMe 帮你无缝恢复

#### 场景 C：31 天完全没访问
```
Day 0  登录 → JSESSIONID(剩7天) + rememberMe(剩30天)
... 31 天没访问 ...
Day 31 访问 → JSESSIONID 过期 ❌  +  rememberMe 过期 ❌
              → 必须重新登录 🔒
```

### 4. 代码实现位置

#### 后端 Shiro 配置

文件：`backend/src/main/java/com/tanwb/navigation/config/ShiroConfig.java`

```java
// Session 滑动过期（7 天）
@Bean
public DefaultWebSessionManager sessionManager() {
    DefaultWebSessionManager sessionManager = new DefaultWebSessionManager();
    sessionManager.setGlobalSessionTimeout(7 * 24 * 60 * 60 * 1000L); // 7 天
    sessionManager.setSessionValidationSchedulerEnabled(true); // 开启滑动
    return sessionManager;
}

// RememberMe Cookie（30 天）
@Bean
public SimpleCookie rememberMeCookie() {
    SimpleCookie cookie = new SimpleCookie("rememberMe");
    cookie.setMaxAge(30 * 24 * 60 * 60); // 30 天固定过期
    cookie.setHttpOnly(true);
    return cookie;
}
```

#### 前端记住我选项

文件：`frontend/src/components/AuthDialog.vue`

```vue
<el-checkbox v-model="loginForm.rememberMe">记住我（30天自动登录）</el-checkbox>
```

#### 后端 DTO 与 Service 接收

|------|------|
| `dto/LoginRequest.java` | 新增 `Boolean rememberMe` 字段 |
| `service/AuthService.java` | `new UsernamePasswordToken(user, pass, rememberMe)` |

### 5. 如何调整过期时间？

**如果你想改成：半年不用也能自动登录**

修改两处：

1. **`ShiroConfig.java`** 调整 RememberMe Cookie：
   ```java
   cookie.setMaxAge(180 * 24 * 60 * 60); // 180 天（半年）
   ```

2. **`ShiroConfig.java`** 调整 Session 滑动过期：
   ```java
   sessionManager.setGlobalSessionTimeout(14 * 24 * 60 * 60 * 1000L); // 14 天滑动
   ```

| 你希望的体验 | Session（滑动） | RememberMe（固定） |
|-------------|----------------|-------------------|
| 银行级安全（20 分钟无操作即下线） | 20 分钟 | ❌ 禁用 |
| 普通网站（几天不访问再回来要重登） | 7 天 | 7 天 |
| 本项目默认（偶尔用也能保持很久） | **7 天** | **30 天** |
| 像豆包一样"几乎从不失效" | 30 天 | 180 天 |

## 四、AlwaysData 部署方案（推荐）

### 1. 架构说明

将前端和后端部署到 AlwaysData，使用 Node.js 作为前端服务 + API 代理层。

```
浏览器 → tanyouwei.alwaysdata.net (Node.js server.js)
         ↓ 同源 /api/auth/me
       server.js 代理
         ↓
       services-tanyouwei.alwaysdata.net:8380
         ↓
       后端 Java 返回响应
```

### 2. 部署步骤

#### 步骤 1：修改前端配置

**`.env.production`**：
```
# 空值 = 走同源 /api 路径，由 server.js 代理转发
VITE_API_BASE_URL=
```

**关键点**：`baseURL` 为空时，axios 请求 `/api/auth/me` 会变成同源请求 `/api/auth/me`，由 server.js 代理到后端。

#### 步骤 2：创建 server.js（零依赖）

```javascript
import http from 'http';
import fs from 'fs';
import path from 'path';
import { fileURLToPath } from 'url';

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

const PORT = Number(process.env.PORT || 3000);
const HOST = process.env.IP || '0.0.0.0';

// 后端地址：注意 AlwaysData 做了进程隔离，必须用域名而不是 localhost
const BACKEND_HOST = process.env.BACKEND_HOST || 'services-tanyouwei.alwaysdata.net';
const BACKEND_PORT = Number(process.env.BACKEND_PORT || 8380);
const BACKEND_ORIGIN = `http://${BACKEND_HOST}:${BACKEND_PORT}`;

const DIST_DIR = path.join(__dirname, 'dist');

// MIME 类型映射
const MIME_TYPES = {
  '.html': 'text/html; charset=utf-8',
  '.css': 'text/css; charset=utf-8',
  '.js': 'application/javascript; charset=utf-8',
  '.json': 'application/json; charset=utf-8',
  '.svg': 'image/svg+xml',
  '.png': 'image/png',
  '.jpg': 'image/jpeg',
  '.ico': 'image/x-icon',
  '.woff': 'font/woff',
  '.woff2': 'font/woff2',
};

// 静态文件服务
function serveStatic(req, res) {
  const urlPath = decodeURIComponent(req.url.split('?')[0]);
  let filePath;
  if (urlPath === '/') {
    filePath = path.join(DIST_DIR, 'index.html');
  } else {
    filePath = path.normalize(path.join(DIST_DIR, urlPath));
    if (!filePath.startsWith(DIST_DIR)) {
      res.writeHead(403);
      return res.end('Forbidden');
    }
  }

  fs.stat(filePath, (err, stat) => {
    if (!err && stat.isFile()) {
      const ext = path.extname(filePath).toLowerCase();
      res.writeHead(200, {
        'Content-Type': MIME_TYPES[ext] || 'application/octet-stream',
        'Cache-Control': ext === '.html' ? 'no-store' : 'public, max-age=31536000',
      });
      return fs.createReadStream(filePath).pipe(res);
    }
    // SPA fallback：找不到文件返回 index.html
    const fallback = path.join(DIST_DIR, 'index.html');
    fs.stat(fallback, (e) => {
      if (e) {
        res.writeHead(404);
        return res.end('Not Found');
      }
      res.writeHead(200, {
        'Content-Type': MIME_TYPES['.html'],
        'Cache-Control': 'no-store',
      });
      fs.createReadStream(fallback).pipe(res);
    });
  });
}

// API 代理
function proxyApi(req, res) {
  const options = {
    hostname: BACKEND_HOST,
    port: BACKEND_PORT,
    path: req.url,
    method: req.method,
    headers: {
      ...req.headers,
      host: `${BACKEND_HOST}:${BACKEND_PORT}`,
      origin: BACKEND_ORIGIN,
      referer: BACKEND_ORIGIN,
      connection: 'close',
    },
  };

  const proxyReq = http.request(options, (proxyRes) => {
    const headers = { ...proxyRes.headers };
    delete headers['content-length'];
    delete headers['transfer-encoding'];
    delete headers['connection'];
    res.writeHead(proxyRes.statusCode, headers);
    proxyRes.pipe(res);
  });

  proxyReq.on('error', (err) => {
    res.writeHead(502, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ error: 'Backend unavailable', detail: err.message }));
  });

  proxyReq.on('timeout', () => proxyReq.destroy());
  proxyReq.setTimeout(60000);

  req.pipe(proxyReq);
}

// 创建服务器
const server = http.createServer((req, res) => {
  if (req.url.startsWith('/api/') || req.url === '/api') {
    return proxyApi(req, res);
  }
  serveStatic(req, res);
});

server.listen(PORT, HOST, () => {
  console.log(`Frontend server running on ${HOST}:${PORT}`);
});
```

### 3. 常见问题

#### 问题：进程被 SIGKILL 杀掉（exit code 137）

**原因**：AlwaysData 对 Node.js 应用的内存限制。

**解决方案**：
- 关闭不必要的浏览器标签页
- 检查 AlwaysData 后台的内存使用情况

#### 问题：Node.js 连不上后端（localhost:8380）

**原因**：AlwaysData 对不同应用做了进程/网络隔离。

**解决方案**：server.js 中 BACKEND_HOST 必须使用域名：
```javascript
const BACKEND_HOST = 'services-tanyouwei.alwaysdata.net';  // 不能用 localhost
```

**验证方法**：SSH 执行
```bash
# 测试 localhost（会失败）
curl -s http://localhost:8380/api/auth/me

# 测试域名（会成功）
curl -s http://services-tanyouwei.alwaysdata.net:8380/api/auth/me
```

#### 问题：刷新后登录状态丢失

**原因**：前端和后端域名是跨站的，SameSite=Lax 阻止 Cookie。

**解决方案**：AlwaysData 方案中，前端和后端是同站的（eTLD+1 相同），Cookie 不会丢失。

## 五、GitHub Pages 部署问题

### 1. Cookie 丢失问题

#### 问题描述
- GitHub Pages 登录成功后，刷新页面登录状态丢失
- 后端日志显示 `No mapping for GET /api/api/auth/me`（路径重复）

#### 根本原因

**问题链路**：
```
浏览器 → https://mryouwei.github.io/webpage-navigation/
         ↓
       Cloudflare Worker（代理）
         ↓
       https://api-proxy.xxx.workers.dev/api/auth/login
         ↓
       AlwaysData Worker 配置错误 → /api/api/auth/login
```

**两个核心问题**：

1. **路径重复拼接**：Worker 代码中错误添加了 `/api` 前缀
2. **Cookie 跨站**：GitHub Pages 和 Worker 域名不同，浏览器阻止跨站 Cookie

#### 解决方案

**方案 A：修复 Cloudflare Worker（如果坚持用 GitHub Pages）**

修改 Worker 代码，移除路径拼接：
```javascript
// 错误：不要添加 /api 前缀
// url.pathname = '/api' + url.pathname;

// 正确：直接用原始路径
url.pathname = url.pathname;
```

**Cookie 问题**：需要在 Worker 响应中重写 Set-Cookie：
```javascript
if (response.headers.get('set-cookie')) {
  const cookie = response.headers.get('set-cookie')
    .replace(/Domain=[^;]*/g, '')
    .replace(/SameSite=[^;]*/g, 'SameSite=None; Secure')
  response.headers.set('Set-Cookie', cookie)
}
```

**方案 B：改用 AlwaysData 部署（推荐）**

详见第四章节的 AlwaysData 部署方案。

### 方案 A：Vercel Serverless Functions

**步骤**：

1. 注册 Vercel（用 GitHub 账号登录）
2. 创建项目，在项目根目录创建 `api/proxy.js`：

```javascript
export default async function handler(req, res) {
  const { url } = req.query;
  const targetUrl = `http://services-tanyouwei.alwaysdata.net:8380${url}`;
  
  try {
    const response = await fetch(targetUrl, {
      method: req.method,
      headers: { ...req.headers, origin: 'http://localhost:8381' },
      body: req.method !== 'GET' && req.method !== 'HEAD' ? req.body : undefined
    });
    
    res.setHeader('Access-Control-Allow-Origin', '*');
    res.setHeader('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE, OPTIONS');
    res.setHeader('Access-Control-Allow-Headers', 'Content-Type, Authorization');
    
    const data = await response.text();
    res.status(response.status).send(data);
  } catch (error) {
    res.status(500).send({ error: error.message });
  }
}
```

3. 部署后获取 HTTPS 地址

const http = require('http');

exports.handler = async (event, context) => {
