# 网页导航项目 - 常见问题与解决方案

本文档记录了在开发过程中遇到的核心问题及其解决方案，涵盖 Git 管理、打包部署、跨域访问三大类。

---

## 一、Git 管理

### 1. .gitignore 配置问题

#### 问题描述
- 前端大量文件（node_modules, dist 等）显示在提交列表中，导致 git status 混乱。
- 已提交的 gitignore 规则未生效。

#### 解决方案
- **配置正确的 .gitignore**：
  ```
  # Node.js / Frontend
  node_modules/
  dist/
  dist-ssr/
  *.local

  # IDE
  .idea/
  .vscode/

  # OS
  .DS_Store
  Thumbs.db
  ```
- **清除已被追踪的文件**：如果文件已经被提交到 git 历史，需要先从 git 缓存中移除：
  ```bash
  git rm -r --cached node_modules
  git rm -r --cached dist
  ```

### 2. Git 推送与远程仓库管理

#### 问题描述
- 本地有多个远程仓库（origin / github），容易推错。
- 分支没有设置 upstream，裸写 `git push` 报错。

#### 解决方案
- **查看远程仓库**：`git remote -v`
- **设置默认跟踪分支**：
  ```bash
  git push --set-upstream origin master
  # 之后裸写 git push 就会默认推到 origin 的 master 分支
  ```
- **添加/修改远程仓库**：
  ```bash
  git remote add origin <仓库地址>
  git remote set-url origin <新仓库地址>
  ```

## 二、打包与部署

### 1. Vite 打包后资源路径错误

#### 问题描述
- 部署到 GitHub Pages 后，页面白屏，控制台报 404 错误（资源加载失败）。
- 原因：vite.config.js 中 base 路径未配置或配置错误。

#### 解决方案
- 在 `vite.config.js` 中配置 `base`：
  ```javascript
  export default defineConfig({
    // 如果部署到 https://用户名.github.io/仓库名/
    // base 必须与仓库名一致
    base: '/你的仓库名/',
    // ...
  });
  ```
- **注意**：修改 base 后，`npm run preview` 本地预览时也要带上这个路径才能访问：
  - `http://localhost:4173/仓库名/`

### 2. GitHub Pages 部署失败

#### 问题描述
- GitHub Actions 构建失败。
- `pages build and deployment` 报错。

#### 解决方案
- **方案 A：手动推 gh-pages 分支（推荐）**
  ```bash
  # 1. 在 frontend 目录下 build
  npm run build
  
  # 2. 进入 dist 目录，初始化 git 仓
  cd dist
  git init
  git add -A
  git commit -m "deploy"
  
  # 3. 推送到远程仓库的 gh-pages 分支
  git remote add origin <仓库地址>
  git branch -M gh-pages
  git push -f origin gh-pages
  
  # 4. GitHub Pages 设置 → 来源选 "从分支部署"，分支选 "gh-pages"
  ```
- **方案 B：GitHub Actions 自动部署**
  - 创建 `.github/workflows/deploy.yml`，配置 CI/CD 流程
  - 在 GitHub Pages 设置中切换到 "GitHub Actions"

### 3. 本地 preview 端口不匹配

#### 问题描述
- 本地 `npm run preview` 启动后，访问 `http://localhost:8381` 打不开页面。

#### 解决方案
- Vite 默认 preview 端口是 4173
- 自定义端口在 `vite.config.js` 中配置 `preview.port`
- 如果配置了 base，访问地址必须带 base 路径

## 三、跨域与网络访问

### 1. Mixed Content 混合内容拦截（HTTPS 页面请求 HTTP API）

#### 问题描述
- GitHub Pages 是 HTTPS 站点，但后端 API 使用 HTTP（AlwaysData 免费版不支持 HTTPS）
- 浏览器直接拦截所有跨域请求，页面功能完全失效

#### 解决方案：Cloudflare Worker 反向代理

**核心思路**：在 GitHub Pages 和 AlwaysData 之间加一层 Cloudflare Worker 作为 HTTPS 中转站。

**步骤 1**：注册 Cloudflare
- 打开 https://dash.cloudflare.com
- 使用邮箱免费注册，无需信用卡

**步骤 2**：创建 Worker 并配置代理
- 在 Workers & Pages 里创建新 Worker
- 粘贴以下代码：

```javascript
export default {
  async fetch(request) {
    const url = new URL(request.url);
    url.hostname = '你的后端域名';  // 如 services-tanyouwei.alwaysdata.net
    url.port = '8380';
    url.protocol = 'http:';
    
    // 处理 CORS 预检请求
    if (request.method === 'OPTIONS') {
      const origin = request.headers.get('Origin') || '*';
      return new Response(null, {
        status: 204,
        headers: {
          'Access-Control-Allow-Origin': origin,
          'Access-Control-Allow-Methods': 'GET, POST, PUT, DELETE, OPTIONS',
          'Access-Control-Allow-Headers': 'Content-Type, Authorization',
          'Access-Control-Allow-Credentials': 'true'
        }
      });
    }
    
    const modifiedHeaders = new Headers(request.headers);
    // 关键：设置为后端 CORS 白名单已有的 Origin，绕过检查
    modifiedHeaders.set('Origin', 'http://localhost:8381');
    
    const modifiedRequest = new Request(url, {
      method: request.method,
      headers: modifiedHeaders,
      body: request.body,
      redirect: request.redirect
    });
    
    const response = await fetch(modifiedRequest);
    
    const requestOrigin = request.headers.get('Origin') || '*';
    const newResponse = new Response(response.body, response);
    newResponse.headers.set('Access-Control-Allow-Origin', requestOrigin);
    newResponse.headers.set('Access-Control-Allow-Credentials', 'true');
    newResponse.headers.set('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE, OPTIONS');
    
    return newResponse;
  }
}
```

**步骤 3**：修改前端配置
- `.env.production` 中的 `VITE_API_BASE_URL` 改为 Worker 地址：
  ```
  VITE_API_BASE_URL=https://你的-worker-name.workers.dev
  ```

**注意事项**：
- 不要在 Worker 代码中拼接 `/api` 路径，前端请求已经带了
- CORS 响应头必须使用动态 Origin（不能用 `*`），配合 `Credentials: true`
- Origin 头改为后端 CORS 白名单已有的值（如 `http://localhost:8381`）

### 2. AlwaysData 后端服务 502

#### 问题描述
- 访问 AlwaysData 后端 API 返回 502 Bad Gateway

#### 解决方案
- **检查端口**：AlwaysData 可能分配了不同的端口，修改 `application.yml` 的 port 为实际监听端口
- **检查进程**：AlwaysData 后台确认 Java 进程是否存活
- **检查 SSL**：免费版不支持 HTTPS，需用 Cloudflare Worker 代理

### 3. 后端 CORS 配置

#### 问题描述
- 本地开发正常，部署到 GitHub Pages 后 API 请求被 CORS 拦截

#### 解决方案
- 在后端 `application.yml` 的 CORS 白名单中加入以下域名：
  ```yaml
  app:
    cors:
      allowed-origins:
        - http://localhost:8381      # 本地开发
        - https://mryouwei.github.io  # GitHub Pages
        - https://*.workers.dev      # Cloudflare Worker
  ```

### 4. 为什么 GitHub Pages 不能直接访问 Alwaysdata 服务？

#### 问题描述
- 前端部署在 `https://mryouwei.github.io/...`，后端 API 地址是 `http://services-tanyouwei.alwaysdata.net:8380`
- 直接直连 API 时页面功能失效，请求被浏览器拦截

#### 根本原因：混合内容策略（Mixed Content Policy）

浏览器安全策略规定：**HTTPS 页面不允许发起 HTTP 请求**。

| 项目 | 协议 |
|------|------|
| GitHub Pages | `https://`（GitHub 强制 HTTPS） |
| Alwaysdata 后端（8380 端口） | `http://`（免费版不支持自定义端口 HTTPS） |

当前端页面运行在 `https://...` 域名下时，浏览器会直接阻止向 `http://...` 发起的请求，控制台会报类似错误：
```
Mixed Content: The page at 'https://...' was loaded over HTTPS,
but requested an insecure resource 'http://...'.
This request has been blocked; the content must be served over HTTPS.
```

**Alwaysdata 免费版限制**：8380 端口走的是 HTTP，免费套餐通常不支持给非标准端口绑定 SSL 证书，因此无法直接把后端改成 HTTPS。

### 5. 为什么代理中转不能在 GitHub Pages 上做，而要用 Cloudflare Worker？

#### 问题描述
- 既然 GitHub Pages 能托管前端代码，为什么不能顺便做一层代理中转？
- 为什么必须额外引入 Cloudflare Worker / Vercel Functions 这类服务？

#### 根本原因：GitHub Pages 是纯静态托管，没有服务端运行时

GitHub Pages 的能力边界：
- ✅ 托管 HTML / CSS / JS 静态文件
- ✅ 提供静态文件下载
- ✅ 通过 `_redirects` 做简单 301/302 重定向
- ❌ **不能发起服务端请求**（所有请求都必须从用户浏览器发出，无法"服务器代发"）
- ❌ **不能修改请求头/响应头**（无法注入 CORS、修改 Origin、加 Token）
- ❌ **不能做协议转换**（没有中间层来做 HTTPS → HTTP 的降级）
- ❌ **没有 Node.js / Python / Java 等运行时**（无法跑 Express、Nginx 等反向代理程序）

而 Cloudflare Worker 具备服务端 JavaScript 运行时，能解决以上所有问题：

```
用户浏览器 (HTTPS)
    └─→ Cloudflare Worker (HTTPS，有运行时)
            └─→ Worker 内部发起服务端 fetch → http://services-tanyouwei.alwaysdata.net:8380 (HTTP)
                    └─→ Worker 给响应加好 CORS 头 → 返回给浏览器
```

浏览器看到的整条链路都是 HTTPS，同时 CORS 也由 Worker 统一处理，不会触发任何拦截。

#### 替代方案参考

如果不想用 Cloudflare Worker，以下几种方案同样可行：

| 方案 | 说明 | 成本 |
|------|------|------|
| Cloudflare Workers（当前方案） | 边缘计算，免费额度 10 万请求/天 | 免费 ✓ |
| Alwaysdata 启用 HTTPS | 将后端改到 443 标准端口并配 SSL | 可能需升级付费套餐 |
| Vercel / Netlify Functions | Serverless Functions 写代理接口 | 免费额度够用 |
| Railway / Render 等 PaaS | 平台默认提供 HTTPS 域名 | 免费额度有限 |
| Nginx 反向代理 | 自己有服务器时，Nginx 做 HTTPS→HTTP 反代 | 需要服务器 |

## 附录：开发流程总结

### 本地开发
```bash
# 终端 1：启动后端
cd backend && mvn spring-boot:run

# 终端 2：启动前端（开发模式，带代理）
cd frontend && npm run dev
# 访问 http://localhost:8381
```

### 生产部署
```bash
# 1. 前端 build
cd frontend && npm run build

# 2. 推到 GitHub Pages
cd dist
git init && git add -A
git commit -m "deploy"
git remote add origin <仓库地址>
git branch -M gh-pages
git push -f origin gh-pages

# 3. 后端部署
# 上传 jar 到 AlwaysData 并重启
```

### 配置文件清单
| 文件 | 作用 |
|------|------|
| `frontend/vite.config.js` | Vite 配置（base, proxy, port） |
| `frontend/.env.development` | 开发环境变量（API 地址等） |
| `frontend/.env.production` | 生产环境变量（API 地址等） |
| `backend/src/main/resources/application.yml` | 后端配置（端口、CORS、数据源等） |
